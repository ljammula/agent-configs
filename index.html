Open items

Per-task timeout budgets (30/45 min) predate thinking being enabled and haven't been revisited — the 8/17 hardened-config rerun found 3/7 harness arms (43%) failing to complete inside them. That run's 2:15-4:46 PM window overlapped with other local inference contesting the same host's resources; a clean-restart rerun of the worst case (go-flutter/bookmarks-app, zero diff/zero turns originally) passed cleanly in 18 min with a real 328-line diff — resolved as contention-caused, not a genuine stall. dart/sequential-runner's settlement-speed timeout and the ~312% overhead figure are not yet re-isolated the same way.

Background-process kills on long unattended /goal runs — mechanism class identified, exact enforcing code not yet traced; a 2/2 correlation with aggressive compaction settings is a new, unconfirmed lead.

Settlement-triggered corrective follow-ups (quality-gate.ts, cross-model-review.ts) confirmed to silently not fire (n=3) — this, not a regression of the thinking/temperature fix, is why the go/lru-cache battery-script run failed despite the reviewer correctly catching the bug. A same-day fix attempt was reverted after an independent review found the diagnosis itself was wrong: sendUserMessage from agent_settled doesn't queue a turn at all, it starts a nested re-entrant run, so "wait for the turn to start" doesn't address the real failure. The race-free fix has to inject from agent_end instead — still open.

quality-gate.ts runtime overhead was median 100.3% pre-hardening, still above the plan's 20% screening threshold — now ~312% on thinking-enabled turns (not yet re-isolated from the contention window above), sharpening the same open question.

TypeScript/JS task fixtures still need battery coverage — routed and unit-tested only so far.
