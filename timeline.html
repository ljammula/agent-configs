Docker containment proven live; auto-compaction bug fixed

Docker containment verified live via Colima: image and launcher build and run under Pi 0.83.0, and pi/containment/verify-live.sh passes all 17 checks — workspace-only writes, escape attempts, host-credential and socket absence, network denial, /tmp noexec, capabilities, no-new-privileges. /goal command and the zero-human build orchestrator ship

Two new pieces of infrastructure landed the same day: goal-gate.ts, a session-scoped /goal <condition> command gated on the most recent broad verification actually passing against the current diff (not self-report); and build_app.py, an orchestrator that drives bounded pi -p corrective rounds outside chat and always writes a BUILD_REPORT.md. A settlement-time reviewer trigger also shipped, mitigating cross-model-review.ts's blind spot on suites whose verification command never runs inside the model's own session. Two kickoff-race and false-rejection bugs in goal-gate were found and fixed the same day.

goal-gate hardened against real failure modes; TUI crash root-caused

goal-gate.ts's verification evidence was bound to the diff hash it ran against, then hardened against models that never emit the completion marker. Qwen3.8 migration lands; comparison finds a clean, replicated failure

The local provider migrated to Qwen3.8-27B-8bit, live-validated end to end (read/edit/test loop, settlement gate, independent reviewer, full deterministic suite). A same-day comparison against claude-sonnet-5 on go/lru-cache then found a stark gap: Claude passed 3/3 all-time on this task; Qwen3.8 went 0/4 across four live trials, producing the identical key/value-confusion eviction bug every time — with cross-model-review.ts independently catching that same bug 4/4 times without the model acting on the diagnosis. Two new extensions built in response, progress-stall-guard.ts and wall-clock-budget-nudge.ts, each had a real bug found and fixed live during the same trials. A genuine gap in the task's own hidden tests was also found and fixed (every eviction test used key == value, so this exact bug scored a false pass).

Aug 17
2026-08-17
4/4 replicated

Root cause found: thinking was off, decoding was greedy — fix replicates 4/4

The Aug 16 failure's root cause: the Qwen3.8 route was silently running with thinking disabled and undocumented greedy decoding (mlx-vlm defaults to temperature: 0.0 when unset, and pi-coding-agent has no flag of its own to override it). Enabling thinking alone caused a real regression first — a developer-role message rejected with a 503 on every turn — fixed by forcing the relevant compat flag off. With both fixes in place: 4/4 on the exact same task (trials 6–9), correct key-based fix, 100% coverage each time, matching the regression test added because of the Aug 16 finding — trial 9 passed even under real, log-confirmed GPU contention. Result written up as a standalone report and the project's overview landing page shipped the same day.
